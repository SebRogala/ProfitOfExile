## Goal

poe.ninja's gem endpoint serves a per-line sample size (`count`) and a price-history sparkline (`sparkLine.data`), and the collector drops both today (`internal/collector/ninja.go:43-56`). When every WI has landed, the collector parses both, `gem_snapshots` stores them in nullable columns, and every lab analysis run receives them on `GemPrice` through the shared loaders. Lab derives a per-variant thin-sample flag from the count alone (`count <= 5`, lock L6). Rows stored before the change read as sample unknown, never as thin. How a thin gem is priced, ranked or shown is POE-299's scope (ADR-027 § Decision 4), not this plan's.

## Decisions

- **D1 — Carry the sample as `SampleCount *int` and the sparkline state as `SparklineEmpty *bool`, nil meaning unknown.** Add both fields to `GemSnapshot` (`internal/collector/fetcher.go:13-22`) and to `GemPrice` (`internal/lab/transfigure.go:39-47`). The parser sets `SampleCount` only when the payload carries `count`, and sets `SparklineEmpty` only when the payload carries `sparkLine`. *Not chosen:* `int` / `bool` value fields — a zero count from an absent key reads as thin, which breaks AC EC2; the `ninjaItemLine.Count int` shape (`ninja.go:96`) has the same defect for the item table and is out of scope here.
- **D2 — A sparkline is empty when `sparkLine` is present and its `data` array has zero entries.** A `sparkLine` key that is absent or `null` gives `SparklineEmpty == nil`. A present `sparkLine` with an absent or `null` `data` key counts as empty, because it carries no history point. Decode `data` as `[]json.RawMessage`: emptiness depends on the array length alone, so the point values need no numeric decode, and a `null` entry counts as one point. *Not chosen:* decoding `data` as `[]float64` — it decodes values nothing reads (a `null` point decodes to 0 without error, the scalar-null rule `internal/collector/ninja.go:73-76` records), and it ties the parser to a numeric point type the decision does not need.
- **D3 — Thin is `SampleCount != nil && *SampleCount <= 5`; the sparkline never decides it.** Lock L6 and ADR-027 § Decision 3 set the threshold; tracker EC1 (Ice Crash of Cadence 20/20: count 2, sparkline present → thin) rules out the sparkline as the rule. Name the threshold `labThinSampleCount = 5` beside `labTierCutoffChaos` in `internal/lab/classification.go`, with a comment citing L6. *Not chosen:* a percentile-based threshold (AGENTS.md § Modeling rules, "Absolute cutoffs … are suspect") — the owner fixed the absolute value on 2026-10-14 (L6).
- **D4 — Thin-sample is a lab property, outside `internal/price/tier`.** Expose it as the method `func (g GemPrice) ThinSample() bool` in `internal/lab/classification.go`. Leave `tier.Classify`, `tier.LowConfidence`, TOP detection and Font EV unchanged. ADR-026 § Decision 3 (callers own eligibility) and ADR-027 § Consequences ("the thin-sample flag is set in `internal/lab`") bind this. *Not chosen:* a `tier.Item` field — it moves Lab policy into the shared leaf package.
- **D5 — Add two nullable columns, `sample_count INTEGER` and `sparkline_empty BOOLEAN`, with no default and no backfill.** `gem_snapshots` is a compressed hypertable (`20260723160017_league_scope_gem_snapshots.up.sql:43-48`). Keep both columns out of the primary key, out of `compress_segmentby` / `compress_orderby`, and out of `gem_snapshots_hourly` / `gem_snapshots_daily`: they do not distinguish rows, so the backend profile's "Row identity" rule (`.claude/agents/backend.md` § Hypertable migrations) does not apply. *Not chosen:* `NOT NULL DEFAULT 0` as `item_snapshots.sample_count` does (`20260906024420_create_item_snapshots.up.sql:77`) — a 0 default reads as thin for all history, against EC2 (MCP discoveries POE-296, auto-confirmed fork).
- **D6 — Store the sparkline flag beside the count.** The flag never decides thin (D3); it stays for diagnostics and backtests (MCP discoveries POE-296, auto-confirmed fork). The collector stores both raw values unfiltered (AGENTS.md § Modeling rules, "The collector stores everything upstream serves").
- **D7 — Both `GemPrice` producers read the columns.** `LatestGemPrices` (`internal/lab/repository.go:31`) feeds every `Run*` analysis (`internal/lab/analyzer.go:67,121,194,251,344,390`); `CorruptedGemPricesByNames` (`internal/lab/repository.go:1919`) feeds Dedication. A `GemPrice` from either one then carries the same sample. *Not chosen:* `LatestGemPrices` alone — a Dedication gem would read unknown while its Font twin reads thin.

## Build order

Stage by path: `git add <path>` per path on the WI's `Files:` line. A reviewer reads the WI's own `Files:` set and ignores hunks outside it.
